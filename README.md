# Starlight Bell

マイク入力を光で可視化するビルド不要のPWAです。操作欄の「〈 開始 終了 〉」の左右の矢印で、光の群れと星空を切り替えられます。横へのスライドとともにテーマ名と短いテーマ文を約2.4秒表示します。動きを減らす設定ではスライドを省略します。初期表示は光の群れです。

## 光の群れ

40Hz〜14kHz（上限はナイキスト周波数）の512帯域を、対数スケールで5つに分けます。各帯域は基本の群れと、音が豊かなときに加わる追加の群れを持ち、最大10の群れがそれぞれの周期で登場・退場します。周波数分布の多様さと音全体の強さ・立ち上がりから群れ数の目安を滑らかに変え、単純な音では少数、豊かで激しい音では多くします。楽器数そのものの識別ではありません。予定された発生・消滅は、拍子推定が確かな場合は推定した最終拍や小節頭、それ以外は通常の拍へ寄せます。群れは原則3秒以上維持し、待機は最大約2.2秒に制限します。対称の相手が現れる場合もありますが、常に対にはなりません。

- 群れの発生元は中央の集合点か画面の外側です。中央からの群れの放出、中央から順々に放出された粒子の集合、画面外からのまとまった登場、外周の複数方向からの粒子の集合を交代します。個体数が増えるときも新しい粒子は同じ発生元から移動します。分散中の群れが再び活動するときは、見えている粒子の位置と速度を保ったまま再集合します。
- 大きな球は時々2つへ分裂し、小さな球は近距離でゆっくり接近したときに結合します。質量を基礎半径の2乗（2Dの面積）として扱い、イベント前後の総面積・重心・並進運動量を保存します。分裂の反対向きの力は音から加わる外力の演出で、結合では相対運動のエネルギーを散逸させます。速度上限と約12秒の個体別クールダウンを守り、空き枠だけを再利用するため総スロット数は増えません。
- 球はそれぞれ位置と速度を持ち、加速度を制限して移動します。個体ごとに集まりやすさが異なり、近くの球との進行方向の整列・接近時の反発と、共通の流れを受け、面状の円・ドーナツ・軌道に沿う列・螺旋・帯状の広がりが生まれます。図形上の固定位置への配置は行いません。
- 単独の動きに加え、ときどき左右・上下・点対称の相手が現れます。相手は滑らかに登場・退場します。
- 帯域の強さと群れの周期によって基本の個体数が16〜128球で変化します。サイズは極小粒子（約32%）、通常の球、少数の大きな球（約1.5%）を混ぜています。音への反応でさらに大小が変わり、群れのサイズ・移動速度もそれぞれ異なります。
- 小粒子の一部は群れから漂い出て、別の活動中の群れへ移動し合流します。同じ個体の位置・速度・サイズを保ったまま所属を移し、色は新しい帯域へ滑らかに馴染みます。1群から同時に離れるのは最大2個体で、受け入れは空き枠がある場合だけです。全体の個体スロット数は増やしません。合流先が消えた場合は別の群れを探すか元の流れに戻ります。
- 音色の明るさ、テンポ・音量・音の立ち上がり、音のざらつきとクロマ分布の長調・短調らしさから、曲の雰囲気を近似します。感情や歌詞の意味を正確に認識するものではなく、長調・短調の手がかりも弱い参考として扱います。
- 全色相を候補に持ち、推定した雰囲気は色の分布の緩やかな偏りとして反映します。暖色・寒色・中間の固定パレットへの切り替えは行いません。明るさ・勢い・緊張感・和音の手がかりが連続的に変わり、どの傾向でもすべての色相が残ります。群れ・周波数・個体差と拍の色変化も重ね、約6秒かけて馴染ませます。
- 雰囲気の傾向が続いていても、ときどき色の偏りを緩め、全色相の分布へ約2〜3秒で開きます。約2秒保った後、約3秒でその時点の雰囲気の傾向へ戻ります。傾向の推定自体は止めません。周期には幅を持たせ、認識できる場合は開始を拍・小節頭へ寄せます。
- 約1.8%の個体は、配色の傾向から外れた色を持ちます。例外になる個体は固定し、色の小さな揺らぎだけをゆっくり変化させ、フレームごとのランダムな点滅を避けます。
- 消滅は中央集合、外への発散、渦を巻いた中央集合、渦を巻いた発散の4種類。群れが再登場するたびに変わります。
- 流れの中心は速度に上限を持つ慣性移動をし、球は自分の速度で泳ぎます。旋回は角速度と加速度の上限で滑らかにします。光の尾は直近0.16秒以内の実際の移動履歴から描く短い曲線で、後方ほど細く淡く消えます。長さを制限し、停止・再登場時に古い軌跡をつなぎません。拍への発光は即座、移動速度は約0.5秒で追従し、広がりには短い慣性を持たせます。
- 低音〜高音のスペクトルの立ち上がりと、その間隔から60〜180 BPMのテンポ・拍位置・推定の確かさを認識します。安定するまで数秒かかり、曲によって半分・倍のテンポに解釈する場合があります。拍間隔は幅を持って評価し、直近の間隔の中央値と緩やかな位相補正で演奏の揺れを吸収しつつ、徐々に変わるテンポにも追従します。
- 認識したテンポで群れの軌道・個体の移動速度全体を変えます。120 BPMを基準に、遅い曲はゆっくり、速い曲は速くなり、約1.2秒で滑らかに追従します。通常移動・合流・発散・渦・対称側も含めた最高速度をテンポで制限します。群れの中心の上限は個体より低く設定し、短い推定の途切れでは直近の確かなテンポを最大15秒保持します。上限自体も約2秒で滑らかに追従します。
- 確かな拍に合わせて群れの流れを加速・緩和し、広がりも呼吸するように変化させます。4拍周期で軌道と個体の流れを緩やかに曲げ、8拍周期の色の移ろいと1拍ごとの色のアクセントを加えます。この4拍・8拍の色と軌道の周期は演出用です。別途、強拍の繰り返しから3拍系・4拍系と小節内位置を推定します。最低3周期を観測し、均等な強さの拍など曖昧な場合は決めつけません。音だけから4/4と2/2などの音価を確定したり、必ず正しい小節頭を特定するものではありません。短い打音の欠落は拍の時計でつなぎ、不規則な音や静寂では同期を弱めます。個々の音の立ち上がりへの即時反応と移動の慣性は維持します。
- 中央の集合点は数拍かけて上下にゆっくり脈動します。周囲にも最大2つの小さな集合点が時々現れ、薄く消えます。一部の個体が弱く引かれるため、群れ全体を急に引き寄せません。無音では点も消えます。
- 持続音が背景音の差し引きで弱まっても控えめな表示を維持します。音があるのに画面内の全個体が消えた場合は最も強い帯域の休止粒子を中央集合点から放出させ、休止周期による長い空白を防ぎます。実際の無音では通常どおり消滅します。
- 背景は音の周波数重心で色相、音の強さで明るさを変え、滑らかに追従します。

## デバッグ表示

画面左上の「音の認識 · DEBUG」は開閉できます。BPM・BPS（BPM÷60）、テンポの確かさ、推定拍と実際の音の立ち上がりの点灯、推定拍子と小節内の拍、音楽の表情、音色の特徴を表示します。点灯は毎フレーム、数値は約0.15秒間隔で更新し、停止・無音時は入力待ちの表示に戻します。デモ入力は明記します。音色は低域／中域／高域の偏りと倍音的／ノイズ的という音響特徴であり、楽器名は識別しません。

テンポ追跡は獲得時と解除時の条件を分け、過去12秒以内の立ち上がり・同じテンポ候補の持続性・候補の重み（時定数5秒）・現在の拍への位相の一致を組み合わせます。確立したテンポは最後の支持から約8秒間、音が続く間は欠拍をまたいで予測を継続し、その後は支持が戻らなければ徐々に解除します。短い弱音の空白には最低0.6秒、テンポ確立後は約1.4拍分の猶予を設け、遅い曲の拍間の静けさでは時計を失わず、その後も無音が続く場合には速く減衰します。環境音の差し引き前の入力も使い、背景適応で持続音を無音と誤解しません。近くのテンポには連続的に追従し、大きなテンポ変更には複数回・2秒以上の持続した支持を要求します。裏拍やフィルをテンポ変更と混同しないよう、現在の拍の近くの観測間隔を優先します。

拍子推定は、各拍の音量だけでなく、低域・高域の立ち上がりとクロマ変化（和声変化の近似）を、表拍・裏拍に分けて集めます。検出閾値に届かない弱い立ち上がりも使い、テンポ確立時には20Hzで保持した過去12秒の音響特徴を拍の時計に当て直して再利用します。帯域の立ち上がりを拍内の窓で積分し、和声変化は拍ごとに平均したクロマ同士から求め、FFTの単発ピークや打楽器のノイズの影響を抑えます。直近48拍を保持し、新しい拍を重視して3拍周期・4拍周期の再現性を比較します。120 BPMなら最大約24秒、60 BPMなら約48秒、180 BPMなら約16秒です。最低3周期分（3拍子系9拍・4拍子系12拍）と各拍位置の複数観測を要求し、繰り返し候補が勝った場合に採用します。すでに確立した拍子は短いフィル・欠拍では維持し、別の拍子や小節位置へ変えるにはさらに2小節分の継続した支持を要求します。2拍の繰り返しだけから4拍子と断定せず、判断材料が足りない場合は未確定にします。

デバッグ欄には追従中／履歴で継続、最後にテンポを支持した観測からの秒数、3拍・4拍それぞれの候補スコアと差も表示します。表示の「確かさ」や候補スコアは追跡用の指標で、正解率や校正された確率ではありません。

設計上の参考は [Ellis (2007), Beat Tracking by Dynamic Programming](https://www.ee.columbia.edu/~dpwe/pubs/Ellis07-beattrack.pdf) の時間的な連続性と観測の両立、および [Krebs et al. (2016), Downbeat Tracking Using Beat-Synchronous Features and Recurrent Neural Networks](https://www.cp.jku.at/research/papers/Krebs_etal_ISMIR_2016.pdf) の拍同期の帯域別・和声特徴と拍子の持続性です。本実装はこれらの考え方を参考にした軽量な逐次推定で、論文の学習済みRNNやDBNを移植したものではありません。欠拍・裏拍・同音量での音色配置・和声変化・テンポ／拍子変更・曖昧な2拍パターンを合成スペクトルで検証しています。実楽曲データセットでの正解率は未測定です。


## 星空

固定された光が、複数帯域の同時・遅延一致に反応してにじみながら発光します。光ごとに異なる時間で減衰し、条件が合うと流星が現れます。

## 利用

リポジトリのルートで次を実行し、`http://localhost:8000/` を開きます。

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

マイクとService WorkerにはHTTPS（開発時はlocalhost）が必要です。

- 開始：マイク許可を要求し、描画と画面のスリープ防止を開始。
- 終了：描画を停止し、マイクとWake Lockを解放。
- マイクが使えない場合：通知後、再現可能なシミュレーションで動作。
- 録音、保存、音声送信、スピーカーへの出力は行いません。

localStorage・IndexedDBは使用しません。音声は保存しません。Service Workerとマニフェストの範囲はこのディレクトリ内のみです。キャッシュ名は `starlight-bell-soundanimation-` から始まり、それ以外のキャッシュは読み書き・削除しません。

同じオリジンにある別アプリが全キャッシュを削除した場合、このアプリのオフライン用キャッシュも消えます。再びオンラインでページを開くと、必要なファイルが再キャッシュされます。

## 検証

```sh
node tests/app.test.cjs
```

実機では、マイク許可・拒否、準備中の終了、再開始、画面回転、バックグラウンド復帰、ホーム画面への追加、オンラインでの読込後のオフライン起動を確認してください。Wake Lockや全画面表示はブラウザの対応状況によって異なります。

60fps時の仕様の係数を、経過時間で補正して使用します。明順応は待機を挟まず直後から始まり、約0.5秒で落ち着きます。開始するたびに配置を変え、実際の輝きはマイク入力に依存します。

画面右上には、実行中のJavaScriptのバージョンを表示します。現在は `v2026.10.18.12` です。更新時は `app.js` のVERSION、HTMLのJS/CSS URL、Service Workerのキャッシュ名とアセットURLを同じバージョンに更新します。

## 使用マイク指定

「使用マイク指定」を押すたびに最新の入力一覧を取得し、ポップアップ内で選択します。初回に名前が公開されていない場合はマイク許可を要求し、一時取得した入力は解放します。選択名は通常画面にも表示し、開始時はその deviceId を exact 指定します。未指定での開始は自動選択です。実行中の選択変更は旧入力を解放してから再開始します。

接続変更による選択中入力の消失、音声トラックの終了、指定入力の取得失敗を検知した場合は停止し、通知と最新一覧のポップアップを表示します。再選択するまで自動入力には戻しません。iOSがブラウザに公開しない入力は選択できず、Bluetoothの通話表示回避を保証する機能ではありません。停車中にSafari・ホーム画面版で入力切り替え、切断、再選択、音楽再生継続を確認してください。
