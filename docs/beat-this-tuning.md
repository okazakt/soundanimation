# Beat This! マイク解析の改修（v2026.10.18.24）

添付「マイク集音・リアルタイムビート＆拍子分析 チューニング仕様書」の①〜⑤を基に実装。

| 項目 | 実装 |
|---|---|
| 検出器 | Beat This! small0 のみ。BeatNetモデル・CRNN・粒子追跡と従来のテンポ／拍子推定を削除 |
| マイク | echoCancellation / noiseSuppression / autoGainControl = false、mono / 22050Hz要求。実レートからストリーミング変換 |
| フィルタ | 推論入力のみ30Hz HPF → 12kHz LPF → アンチエイリアス付き22,050Hz変換。LPFは入力レートの0.45倍以下に制限 |
| 音量 | DC除去後の窓RMSに合わせて目標0.1・ピーク0.95以下へ調整。元音量の閾値・128倍の上限は廃止。補正後RMS < 0.002で判定 |
| 窓 | 2・4・6…16秒へ拡張、通常2秒間隔。処理が重ければ窓の上限を短縮し間隔を広げる。並行推論せず最新窓を採用 |
| 境界 | 両端0.5秒を除外。中央確率を50Hzの絶対時刻キーで上書き・統合し、履歴は最大32秒 |
| 拍 | max(beat確率, downbeat確率) の背景確率に応じた閾値（最低0.1）の局所最大、強い順に300msのNMS |
| 拍子 | 直近最大32拍、3/4拍子の位相平均。平均≥0.5、他位相との差≥0.15、テンポ整合性≥0.55、最低8拍かつダウンビート位置の2観測を要求 |
| ロック | 同じ拍子・絶対位相の候補が3回連続で支持された場合に採用／変更。スライドで拍インデックスが変わっても絶対時刻で位相を比較 |
| 再同期 | 入力途切れ・レート変更時にリング・確率・拍子履歴を破棄。実行中の古い推論結果も破棄 |

境界除外による0.5秒だけで総遅延は決まらず、推論時間・更新待ちが加算される。デバッグの「確定端」で実測相当の経過を表示し、現在の拍は外挿する。CPUの推論が1秒を超える場合、実際の更新間隔は長くなる。

未準備・失敗・無音時は別方式に切り替えず、拍・BPM・拍子を未確定にする。音量／音色／立ち上がりによる描画は続ける。音声は保存・送信しない。

DBN/HMMはオプションとして保留。まず境界統合・NMS・位相投票を検証し、実録音で残るテンポ／位相ジャンプを評価してから導入を判断する。元入力の固定ゲートはv23で廃止し、補正後の音量で判定する。環境音と音楽は音量だけで区別できないため、モデルの確率の強さと拍間隔の整合性を確認する。

合成確率で3/4拍子、窓スライド、弱いbeat head、欠落ダウンビート、無音、曖昧な出力を検証。音声変換ではブロック境界整合性とエイリアス低減、Workerでは入力ギャップ・レート変更・古い結果の破棄を検証。公開データセットの精度やスマホ実機・残響環境の認識改善率は未測定。

検証結果：`node --test tests/*.test.cjs` は9ファイルすべて成功。Chromiumの合成マイク入力では3/4拍子両音源の120 BPM検出、4拍子音源での4拍子確定、最大8秒での継続推論、モデル取得失敗時の判定停止を確認。3拍子音源では拍子未確定が残った。PWAでは初回保存、オフライン再読込後のモデル再取得なしの推論、入力途切れ後の自動復帰を確認した。

## v22：低音量マイク入力の回帰修正

v21ではRMS 0.003未満を一律に無音扱いし、推論を実行せずゲインを0にしていた。報告画像のiPhone入力RMS 0.0010〜0.0012も遮断しており、解析時間0秒・拍確率0%の原因となった。また、ゲートだけ下げても最大8倍では目標RMSへ届かないため、最大ゲインを128倍へ変更した。

DC除去後のほぼデジタル無音（RMS < 0.00001）のみ省略し、通常の低音量入力は推論する。無音による省略と解析実行中をステータスで区別する。音声の形とアクセント比は窓全体への一定ゲインで保ち、ピーク上限でクリッピングを防ぐ。Beat This!専用の構成とモデルは維持する。

回帰テストではRMS 0.0001〜0.5を含む入力の正規化、報告と同じRMS 0.001のWorker推論実行、デジタル無音・DC・微小ノイズの抑止を確認する。ブラウザ試験は `BEAT_THIS_INPUT_GAIN=0.02 BEAT_THIS_METER=4 node tests/beat-this-browser.cjs` で低音量の合成マイク入力を使用する。iPhone実機の音楽認識精度を直接測定したものではない。

v22検証結果：自動テスト9ファイルすべて成功。低音量ブラウザ試験では、フィルタ・リサンプル後RMS 0.000940、ゲイン約79.0倍でBPM 120・4拍子を検出し、8秒窓での継続推論と停止・モデル読込失敗時の動作も確認した。ゲインは目標RMSだけでなくピーク0.95の上限でも制限される。

## v23：レベル適応を推論・表示の両方へ適用

v22には二つの制限が残っていた。RMSが約0.0001の入力では128倍の補正が不足し、描画とAI採用判定には補正前のスペクトルに基づく無音状態が残っていた。これらを廃止し、入力の現状に合わせたゲインで補正した後の基準に統一した。音声の振幅を小さくしても正規化後の波形は同じになる。大音量には即座に減衰、小音量へは時定数1.2秒で増幅し、10分の1未満への低下が0.3秒以上続けば新しい小音量へ基準を合わせ直す。推論では窓全体への一定ゲインを保ち、強弱・アクセントを潰さない。

モデル側にも一律確率50%のカットによる候補欠落があった。確率履歴の中央値を背景値とし、背景＋（最大値−背景）×0.1（最低0.1）をピーク閾値にする。ただしモデルの反応強度と拍間隔整合性の両方を要求し、単に感度を上げて拍を作り出さない。拍子判定の条件は緩めない。デバッグの拍・小節頭の反応は窓中央の最大値を表示し、検出された最後の一拍がないだけで0%になる表示を修正した。

提供録音による比較では8秒から16〜28秒へ窓を拡大しても確率の低さは解消せず、窓を8秒に維持した。追加の高域通過・スペクトル減算も試験したが、単一録音に合わせたフィルタは採用しなかった。

検証：提供録音を0.07倍にした入力（RMS約0.000100）で、補正約996倍・補正後RMS 0.1となり、実ブラウザのマイク相当入力→Worker→Beat This→描画まで拍候補とBPM推定が出ることを確認した。記録時の候補は約115.4 BPM・内部整合性0.75だったが、正解BPMは不明のため精度を保証する数値ではない。同じ試験で大音量への減衰、さらに小さい音への再適応、デジタル無音の検出を確認した。録音自体や録音由来の確率配列はリポジトリへ追加していない。iPhoneのハードウェア入力経路そのものは未検証。

v23最終検証：`node --test tests/*.test.cjs` は9ファイルすべて成功。通常の合成4拍子音源は120 BPM・4拍子を検出。PWAの初回保存、オフライン起動後の推論、入力途切れ後の再同期は成功。実モデルに増幅後のホワイトノイズ・150Hzの持続音＋ノイズ・デジタル無音を入力した比較では、テンポ整合性指標はそれぞれ0・約0.026・0で、AI採用条件を満たさなかった。これらは限定した試験条件であり、あらゆる環境音で誤検出しないことを保証しない。

## v24：長い文脈、遅延を補う時計、アタック補助

音声リングの上限を16秒へ拡張（22,050Hz、352,800 float32サンプル、約1.35MiB）。通常2秒間隔で2・4・6…16秒の窓を解析し、最初から16秒待たせない。処理時間の1.25倍と2秒の大きい方を次の開始間隔にし（最大8秒）、推論が6秒を超えた長窓は上限を4秒下げる（最低8秒）。10秒を超える長窓の結果は捨て、より短い最新窓で再試行する。短窓でも10秒を超えれば停止する。確率履歴は最大32秒、拍子投票は最大32拍へ拡大し、拍子の支持時刻と参照アンカーを分けて、長い文脈の古いアンカーだけを理由に拍子ロックが消えないようにした。

BeatClockはBeat Thisの確かな拍だけで初期化する。現在時刻−確定した拍の絶対音声時刻を周期で割り、現在の拍・拍内位相・小節位置を外挿する。処理時間・配送時間・境界クロップの影響は既に時刻差に入るため、processingMsを再度引かない。古い結果や順序が逆転した結果は採用しない。

小さなテンポ差は周期を15%ずつ平滑化し、8%以上の周期差は同じ候補が3回以上かつ4秒以上続くまで採用しない。周期の変更時は現在の拍番号と位相を保つ。拍子・小節頭の変更も絶対位相が揃う候補の3回・4秒以上の継続を待つ。弱いAI結果だけでロックを解かない。

音響アタックはFFT窓中心の時刻に合わせ、既存拍の±18%だけ受理する。位相を最大2%/回、周期を最大0.5%/回で補正する。確かなモデルの拍から12秒まで予測し、直近の整合するアタックが3回以上ある場合は24秒まで延長する。裏拍・一発の遅いアタック・低確信のモデル出力だけで延長しない。アタックから新規テンポや拍子を推定する独立エンジンは導入していない。

補正後の無音がmax(0.8秒,1.5拍)続けば停止し、無音後の新しいAIの拍を待つ。入力が以前の10分の1未満へ0.3秒以上落ちた場合も注意状態に入り、3.5拍（最低1秒）以内に新しいAIの拍、または整合する連続3アタックがなければ予測を停止する。小さくなってもリズムが続く音楽は時計を保ち、低い自己雑音だけが残る静寂で古いテンポを長く延長しない。

単独Chromiumで16秒窓の推論は約1.4〜1.5秒、描画プロセス群RSSピーク約616MiB。2秒から16秒まで全段階と16秒での継続を測定した。CPU競合のある試験では上限が12秒へ縮小する挙動も観測した。iPhone実機の性能・認識精度は未測定。

最終検証：自動テスト10ファイル成功。音声時計では遅れた結果の現在位相、単発のテンポ／拍子外れ値、持続的な変更、アタック延長の上限、裏拍の拒否、無音・相対レベル低下・再開を検証。追加の回帰試験では、フィルタの急速に減衰する尾を新しい小音量環境と誤認して再増幅しないことも確認した。合成4拍子音源の120 BPM・4拍子と16秒までの継続を確認し、合成3拍子音源はBPMを検出したものの拍子未確定が残った。PWAのオフライン再起動と入力途切れからの復帰は成功した。測定値は `beat-this-memory-v24.json` に保存した。
